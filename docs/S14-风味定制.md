# S14 风味定制：独立叠加层

日期：2026-10-26

## 一句话结论

曲线编辑器右边多了一组「风味」：下拉选一种声音类型，拖它的手柄改频率和增益，滚轮改 Q。
它是**叠加层**，不是曲线内容——九条固定滤波器只写进 `peace.txt`，不写进 `.peace`，
按「左右」预设各存一份，存在 `ui-state.json` 里。

## 为什么是独立层，而不是往曲线上加点

试过的一种设计是「点一下就在曲线上加一个点」。放弃它的理由不是手感，是结构：

| 需求 | 加点方案 | 独立层方案 |
|---|---|---|
| 风味跟着「左右」预设走 | 点会写进 `.peace`，和预设的曲线混在一起，分不开 | 存在 `ui-state.json` 的 `mainFlavors` 里，按文件名分 |
| 不能增删数量 | 点可以被删掉、被拖走，数量守不住 | 九条由表决定，界面上没有删除入口 |
| 不是调曲线，是叠加 | 用户会以为改的是预设本身 | 只进 `peace.txt`，`.peace` 一个字节都不动 |
| 单独显示 | 只能混在主曲线里 | 曲线图上多画一条叠加量曲线 + 彩色手柄 |

同时保留了「有过渡」的听感：每条风味是一条真实滤波器，钟形/坡形的边界由 Q 决定，
不需要额外写渐变算法。

## 九条类型

按频率升序，也是下拉顺序；前八条颜色按彩虹顺序排（红→橙→黄→黄绿→绿→青→蓝→紫），
最后一条「尖啸」用白色——它只该被削，颜色也跟别人区分开。
配色在 `src/PeaceWpf/Theme/TonePalette.cs`，下拉文字、曲线手柄、每条风味自己的那条曲线共用这一份。

| 键 | 名称 | Lucide 图标 | 颜色 | 覆盖 | 默认频率 | 类型 | 默认 Q |
|---|---|---|---|---|---|---|---|
| boom | 爆炸 | `bomb` | `#F4585C` 红 | 30–150 Hz | 80 Hz | LS 低架 | 0.7 |
| aftershock | 余震 | `waves` | `#F78E3D` 橙 | 150–300 Hz | 220 Hz | PK | 1.0 |
| voiceM | 男声 | `mars` | `#F6C945` 黄 | 300–1200 Hz | 700 Hz | PK | 0.9 |
| voiceF | 女声 | `venus` | `#A8D45A` 黄绿 | 1–3.5 kHz | 1.8 kHz | PK | 0.9 |
| step | 脚步 | `footprints` | `#5CC46A` 绿 | 1.5–4 kHz | 2.5 kHz | PK | 1.0 |
| gun | 枪声 | `crosshair` | `#3FC9C1` 青 | 2–7.5 kHz | 4.5 kHz | PK | 0.9 |
| sibil | 齿音 | `wind` | `#4A9DF0` 蓝 | 5–10 kHz | 7 kHz | PK | 1.6 |
| air | 空间 | `sparkles` | `#A46BE0` 紫 | 10–16 kHz | 12 kHz | HS 高架 | 0.7 |
| shriek | 尖啸 | `zap` | `#FFFFFF` 白 | 16–20 kHz | 17 kHz | PK | 1.2 |

每个频段另有一个**乐器名**，给下拉右边的「游戏 / 乐器」开关用：
爆炸=低音提琴、余震=大提琴、男声=中提琴、女声=小提琴、脚步=长笛、枪声=小号、齿音=唢呐、空间=镲片、尖啸=三角铁。
两条名字都不超过六个字；开关只换文字和图标，不改频率、不改已经存下来的值。
命名视角**跟着「左右」预设走**：`ui-state.json` 的 `mainInstrumentNaming` 按 `.peace` 文件名各存一份，
切预设就跟着换（和 `mainFlavors` / `mainPreAmps` 同一套规则）；更早的单值 `instrumentNaming` 只当兜底。

图标也跟着换：乐器视角每条有自己的剪影（low 到 high 各一个，风格和游戏图标一样是纯描边）。
例外只有一处：自动风味的方向选「男声」或「女声」时，那一条保持「男声 / 女声」和原来的人物图标——
那时整条建议就是在说这件事，换成中提琴或小提琴反而对不上。例外只在自动风味模式里生效，
退回手动编辑就恢复普通的视角规则。

图标来自开源图标库 **Lucide**（<https://lucide.dev>，ISC 许可；`crosshair` 沿用自 Feather，MIT）。
仓库里只保留 24×24 视框的几何路径（`src/PeaceWpf/Theme/FlavorIcons.cs`），不依赖图标字体，
颜色和描边粗细由代码给；许可原文见 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)。

最外侧的爆炸用低架、空间用高架：再往外没有东西可以「过渡」，钟形在边界回落反而错。
尖啸是峰值而不是高架——它落在 16–20 kHz 中间，两端都还有内容。
频点是听感起点值，不是实验室测量——Q 用户能自己滚轮改，所以不必抠到工程值。

### 为什么是九条

原来的八条里，「枪声 4 kHz」和「换弹/机械 5.5 kHz」的带宽盖住了同一段频谱（重叠约 0.75 个倍频程），
等于两条抢一个位置；同时 150–300 Hz 完全空着，而那正是「闷」的位置——爆炸尾音、室内轰鸣、脚步的厚。
所以合并枪声与机械，把空出的槽位给「余震」；再把 16–20 kHz 补成「尖啸」。

### 补充过、但没收的候选

### 补充过、但没收的候选

| 候选 | 频段 | 没收的原因 |
|---|---|---|
| UI 提示音（命中标记、技能就绪） | 1–3 kHz | 和女声中心几乎重合，选「女声」一样能调 |
| 技能音效（能量、魔法） | 2–8 kHz | 横跨枪声/齿音两段，单独一条会重复 |
| 环境声（风、雨底噪） | 200 Hz–2 kHz | 宽带、无明确中心；需要时用宽钟手拖更准 |
| 水声/水下 | 50–500 Hz + 2–6 kHz | 太偏，只有水下关卡用得上 |
| 背景音乐 | 全频 | 不是「一个频段」的事，属于整体风格 |

## 怎么用

| 操作 | 效果 |
|---|---|
| 下拉 | 选类型；每项前面是它的图标，字是它自己的颜色。**「左右」和「低音」两种编辑态都会出现**；列表一律向上弹（它固定在底部工具条上，向下会顶出屏幕） |
| 下拉右边的开关 | 左「游戏」右「乐器」：切两套叫法。游戏视角是爆炸 / 脚步这类听得出来的东西，乐器视角是低音提琴 / 长笛这类同频段的乐器名 |
| 曲线上拖手柄 | 横向改频率（夹在该类型的覆盖范围内）、纵向改增益（夹在 ±30）；两个方向都跟手 |
| 手柄上滚轮 | 改 Q（×1.15 每格），夹在 0.1–30 |
| 右键手柄 | 把这一条的增益归零（频率和 Q 保留），算一步撤回——不是删除 |
| 点曲线空白 | 仍是建 EQ 点，碰不到风味 |

没有「增强 / 减弱」按钮了：增益就是纵向拖，跟 EQ 点的肌肉记忆一致。

图上的关系：**每条风味在曲线图上各画一条自己的曲线**，颜色和下拉的名称一致，选中的那条加粗；
它们画在正在编辑的那条曲线下面，那条曲线还带一圈暗色描边，
所以风味从它下面穿过去也不会把它盖住。
**控制点和图标只画选中的那一条**——能拖的才画，其余只留颜色曲线，免得九条手柄挤在一起分不清点的是谁。
手柄是自己的颜色，圆点上下的图标就是下拉里那个图标——抬的时候在控制点上方，削的时候在下方。

**0 dB 的风味不画曲线**（它没在改变声音）。
例外只在「左右」编辑态：下拉里正选着的那一条即使 0 dB 也把手柄和图标画出来，否则就没有东西可以往上拖。
退出编辑后这个例外失效；右键归零也会立刻让它消失。

## 存储与合并

- `ui-state.json` 新增 `mainFlavors`：`{ "EsportsMain.peace": [ {key, frequencyHz, gainDb, quality, filterType} ×9 ] }`。
- 读取时按表重建：缺的补默认、多的丢掉、越界的夹回来——旧档（没有这个字段）读进来就是九条全平；
  更旧的八条档里 `mech` 这个 key 会被忽略。
- 合并入口只有一条：`EqLayerSet.TryMerge(includeBass, flavor, out merged, out error)`，
  把风味的非 0 dB 条目追加到主层 + 低音层后面统一排序。7 个调用点全部吃这一份。
- 保存：`.peace` 只写两层曲线；`peace.txt` 写「两层 + 风味」的合并结果；风味本身写进 `ui-state.json`。
- 切预设：旧的先记回 `mainFlavors`，再读新的，然后立刻重写 `peace.txt`。

## 和曲线共用一条草稿（保存 / 取消 / 撤回）

风味的改动走的是和曲线同一个 `EqDraft`：草稿状态是「点列表 + 风味」两件一起
（`EditSnapshot`），所以：

| 动作 | 结果 |
|---|---|
| 拖风味手柄 / 滚轮改 Q | 立刻算「还没保存」，保存 / 取消按钮出现，声音当场变 |
| Ctrl+Z | 一步退回一次拖动或一次滚轮，点列表和风味一起退 |
| Ctrl+Y | 重做 |
| 保存 | 曲线写回 `.peace`，风味写进 `ui-state.json`，两者成为新的基线 |
| 取消 | 曲线和风味一起退回上次保存那份，声音跟着退回去 |

一次拖动只算一步：拖动过程只 `PreviewFlavors`，松手才 `Commit`。

## 一个容易被漏掉的坑：取消编辑

「取消」会把 `peace.txt` 还原成试听前的原文，而原文里没有风味——照原样还原，声音里的风味会一起消失。
所以 `RestorePreviewAsync` 还原成功之后补一句：风味不是全平时，用「已保存的两层 + 风味」再写一遍。
写的时候 `announce: false`，不覆盖「已放弃改动」那句状态栏。

## 与撤回栈的关系

风味和曲线共用一条 50 步的撤回栈，顺序就是操作顺序：拖一下风味、再拖一个 EQ 点，
Ctrl+Z 先退点、再退风味。低音层只有点，风味那一半一直是默认值，不影响它自己的撤回。

两种编辑态都能调风味，所以 Ctrl+Z 跟着「最后改过的那一层」走：编低音时顺手拉了风味，
撤回退的是风味；接着拖低音的点，撤回就退点。按钮能不能按也按同一层判断。
