# 主界面扫频（连续扫频实测）

> 这份文档只讲主界面那个「扫频」按钮。自动 EQ 里的「试听扫频」没有实测功能，别混。

## 这是什么

点一下「扫频」会同时做两件事：

1. **放**一遍 10 秒（可调）的对数扫频，20 Hz 一路升到 20 kHz，听到的就是当前这套 EQ；
2. **录**一遍，反卷积成一条传递函数曲线，画成绿色实线。

和自动 EQ 的分频点测不同：那边是每个频点响 260 ms、一个个量；这边是一次扫过全部频率，
拿到的是**连续的**曲线，分辨率到 1% 以内。

## 界面

扫频按钮左边这一排：

```
[平滑 关] [10 秒 ▲▼] [扫频]
```

| 控件 | 说明 |
|---|---|
| 平滑 | 点一次提一档：关 → 最低 → 稍低 → 中度 → 稍高 → 最高。**只影响画面**，数据不动。档位按窗口半径（3/5/9/15/25 点）定义，所以换了扫频时长手感不变 |
| 秒数 | 2–99 秒，步进 1。越长低频越准，等待也越久 |
| 扫频 | 左键：放一遍并测一条；中键：合并；右键：停止 / 清空（见下） |

## 一次扫频的时间线

```
开麦（丢弃开设备的杂音）
  ↓
放扫频（时长 = 输入框的值）
  ├─ 每 50 ms 按瞬时频率切窗量电平 → 绿色曲线边扫边长
  ↓
放完再等 0.5 秒（混响尾巴）
  ↓
停麦、取样本、反卷积 → 整条曲线
  ↓
用反卷积那条覆盖临时线，并把本次量到的延迟存下来
```

## 算法

### 反卷积

录回来的信号除以已知的参考信号（同一段扫频波形），就是通道的传递函数：

```
H(f) = R(f) / S(f)
```

**不需要对齐**。声卡延迟在反卷积里表现为冲激位置的平移，只影响相位，不影响幅度。
这是它比点测省事的地方。

### 分箱与归一化

- **每倍频程点数跟着扫频时长走**：5 秒 48 点、10 秒 96 点、20 秒 192 点、40 秒以上封顶 384。
  依据是频率分辨率 ≈ 1/时长——扫得越久，曲线配得上越细；5 秒给 478 点、20 秒给 1918 点。
- 箱内按**功率**平均，不是 dB 平均——dB 平均会把深坑抬得过分。
- 700–1400 Hz 的均值归一化到 0 dB，和自动 EQ 的灰线同一口径，两条才叠得起来。

### 延迟

`H = R·conj(S)/|S|²` 的逆变换是个冲激，冲激所在位置就是「录到的比放出的晚多久」。

- 存进 `%LOCALAPPDATA%\EasyEQ\sweep-latency.txt`；
- 实时曲线的频率映射用 `f(t − 延迟)`，高频端才不会错位；
- **每次扫频都重新测量并覆盖**——换声卡后第一次扫频就自动对上。

### 实时曲线

- 每 50 ms 一个点，按 `f(t) = f0·(f1/f0)^(t/T)` 取当前频率；
- 窗口至少装 3 个周期（20 Hz → 150 ms，上限 300 ms），固定 50 ms 在 20 Hz 只有一个周期，RMS 会乱跳；
- 参考点：扫到 1 kHz 之前用目前为止的最大值（所以永远 ≤ 0 dB），过 1 kHz 钉住。
  所以扫过 1 kHz 时曲线会整体跳一下，之后不再动。

### 平滑（只作用于显示）

功率域滑动平均。档位按**窗口半径（点）**定义，不按倍频程——这样扫频时长一改（分辨率变了），
同一个档位的手感还是那个手感：

| 档位 | 半径（点） | 10 秒档下的等效宽度 |
|---|---|---|
| 关 | 0 | — |
| 最低 | 3 | 约 1/32 倍频程 |
| 稍低 | 5 | 约 1/19 |
| 中度 | 9 | 约 1/11 |
| 稍高 | 15 | 约 1/6.4 |
| 最高 | 25 | 约 1/3.8 |

窗口越大越顺，但真实的窄峰窄坑会被一起磨平：**看着更顺是真的，看着更准是假的**。
判断某个坑到底多深，切回**关**，或者看中键合并后的那条（合并用原始数据，不受平滑影响）。

改扫频时长会清空已有曲线：分辨率变了，新旧曲线不是同一种尺子，留着叠着看会误判。

### 按像素列取中位数（渲染）

曲线 478 点、画布几百 px，每列挤一两个点时逐点连会显得毛糙。
画之前按列分组、每列取中位数——同列的点不再互相拉扯，峰和坑仍在原来那一列。
不做任何频率上的平均。

## 交互

| 操作 | 效果 |
|---|---|
| 左键「扫频」 | 放一遍并测一条；已有曲线保留，旧的变暗 |
| 中键「扫频」 | 把现有曲线按**功率**平均成一条更亮更粗的线 |
| 右键（扫频中） | 停止：声音、绿线游标、分析任务一起停，临时曲线消失，已存的几条不动 |
| 右键（结束后） | 清空所有绿线 |
| 右键（刚结束 0.5 秒内） | 什么都不做——手还按在键上，防误删 |

最多留 **5 条**，第 6 次挤掉最旧那条。曲线颜色从 0.22 到 1.0 逐渐变亮，最好认的是最亮那条。

## 用它排除驻波

单点测出来的曲线是「设备 × 房间」的乘积，一个位置分不开这两者。要靠**空间**：

1. 把麦克风放在听音位附近，测一条；
2. 挪 15–20 cm，再测一条（别按中键，别清空）；
3. 重复 3–5 次；
4. 中键合并。

**会跟着位置移动的**（在几条线上位置不同、甚至正负颠倒）是房间驻波；
**所有位置都一样的**是设备本身的毛病。

中键那条就是「几个位置都还在」的东西——它才是值得用 EQ 去补的部分。

## 限制

- **峰值能补，凹谷不能补**。谷是相位抵消，往里加多少功率都被抵掉。房间里测到的谷，EQ 只会白耗余量。
- 房间模态的影响主要在 **300 Hz 以下**，而且随位置变化。300 Hz 以上基本被平均掉。
- 时间是定死的：播放和分析共用一张时间表，唯一的自适应是实时曲线那点滞后补偿。
- 高频端的实时曲线会有几十到几百 Hz 的错位（延迟是未知量），**反卷积那条不受影响**。

## 常见问题

**曲线是平的、贴着图底**
麦克风选的是回环（`Streaming` 之类），录到的是自己放的声音。去自动 EQ 里重新选一次对着喇叭的麦克风。

**高频段整体错位**
延迟文件里的值还是旧设备的。完整放完一次扫频就会自动更新；也可以直接删掉
`%LOCALAPPDATA%\EasyEQ\sweep-latency.txt` 重测。

**曲线在 1 kHz 处断一下**
实时曲线的参考点在那里从「当前最大」换成「1 kHz 那一点」。正常现象，之后不再动，扫完会被反卷积那条覆盖。

**看起来还是毛糙**
把秒数加到 20：点间抖动降 3 dB，是真变准，不是画得好看了。
