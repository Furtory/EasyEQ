当前产品语义（三轮修订后的定论）：

| 模式 | 界面上是什么 | 保存时落到哪 |
|---|---|---|
| 均衡 | 底部常驻的 -1…1 左右音量滑块，不用点亮模式按钮 | 拖完自动写进 `peace.txt` 的 `Channel: L/R` + `Preamp` |
| 左右 | 主 EQ 曲线 + 右侧预设下拉 | 写回选中的 `.peace`（默认 `EsportsMain.peace`） |
| 低音 | 第二条 EQ 曲线 + 预设下拉 +「叠加」开关 | 写回选中的 `.peace`（默认 `EsportsBass.peace`），开关关着就不参与合并 |

- 右侧竖排：与曲线等高的增益（Preamp）滑块 + 一条整体响度表；增益拖完 450 ms 自动写 `peace.txt`。
- 两个下拉列出 EqualizerAPO config 目录里所有 `.peace`；切换时当前层先写回旧文件，再载入新文件。
- 「叠加」开关一改就立即保存，不弹询问。
- 曲线改动走草稿，但**立即试听**：改一下就写 `peace.txt`（150 ms 节流），保存才写回预设，取消还原文件、声音退回，撤回 50 步。
- 平衡 / 增益只重写 `peace.txt`，用「已保存」的两层点，不会把未保存的曲线改动提前生效。
- 启动加载优先级：该层的 `.peace` → 本地 `ui-state.json` → `peace.txt`（它可能是合并结果，所以排最后）。
- 标题栏是「电竞调音台」，右上角设置 / 最小化 / 最大化 / 关闭；没有刷新按钮。
- 设置窗口：三栏 —— 运行环境（APO 状态 / 安装 / 连接 / 状态与提示）、常规设置（导出导入、开机自启）、关于软件（版本 / 检查更新 / 主页）。
- 2026-10-24 实机反馈后改版：均衡不再是一个模式按钮，滑块常驻底部、拖完即存；增益（Preamp）从顶栏挪到曲线右侧竖排、与曲线等高；右侧新增竖着的整体响度表（读同一路 WASAPI loopback 的峰值）。

## 一、架构（已实现，作为后续基线）

### 1.1 点模型

| 概念 | 说明 |
|---|---|
| `EqPoint` | 频率、增益、Q、是否端点、稳定 Id；不可变 |
| `EqPointList` | 2–31 个点，按频率升序；端点锁频率；增删改都返回新列表 |
| `EqLayerSet` | 主层 + 低音层；合并规则：主层全收，低音层中间点全收，20 Hz / 20 kHz 端点把增益并进主层同名端点（同频只留一个滤波器） |
| `EqDraft` | 草稿 / 已保存两份状态；脏标记；保存、取消 |
| `UndoStack` | 整份点列表快照，50 步 |

31 只是 Peace 界面的滑杆上限，不是 EqualizerAPO 引擎的限制。2026-10-24 用 `Benchmark.exe` 实测：40 条 `Filter` 全部被解析并生效（第 40 条 +12 dB 让峰值从 -0.3 dB 抬到 +11.7 dB）。官方文档也写明 Filter 的序号 `n` 不被解释、可以省略。

已定：**不设上限**。点模型、单层、合并都不再按 31 截断或拒绝；合并后超过 31 时，状态栏常驻提示「合并 N 个点 · Peace 只显示前 31 个，声音完整生效」。保存照常写三份文件。

### 1.2 文件读写

| 文件 | 谁写 | 说明 |
|---|---|---|
| `%ProgramFiles%\EqualizerAPO\config\<层>.peace` | 前端 | 只替换 `[Frequencies]`/`[Gains]`/`[Qualities]`；其它段保留；新文件套用 `0.peace` 当模板 |
| `%ProgramFiles%\EqualizerAPO\config\peace.txt` | 前端 | 合并后的完整配置，EqualizerAPO 读它 |
| `%LOCALAPPDATA%\PeaceWpf\ui-state.json` | 前端 | 两层曲线、叠加开关、平衡、两个预设名、窗口大小 |
| `%LOCALAPPDATA%\PeaceWpf\peace.txt.bak` | 前端 | 每次保存前备份 |

保存链路：

```
两层点列表
  → PeaceConfig.Save(主 .peace)
  → PeaceConfig.Save(低音 .peace)
  → EqLayerSet.TryMerge()（不设上限）
  → EapoConfig.Build()（Device / Preamp / 可选 Channel+Preamp / Filter…）
  → 备份 peace.txt → 覆盖写
```

### 1.3 线程与 UI

- 文件读写在后台线程；结果通过捕获的 `Dispatcher` 回到 UI 线程（不能依赖 `SynchronizationContext.Current`，启动时它是 null）。
- 曲线控件只发事件，VM 改状态；图形不直接碰文件。

## 四、风险

| 风险 | 影响 | 对策 |
|---|---|---|
| Peace 自己重写 `peace.txt` | 前端的修改被冲掉 | S7 的冲突检测；保存前比对哈希 |
| `.peace` 里是合并结果 | 两层分不开 | 两层以各自预设 + `ui-state.json` 为准；删缓存只剩主层 |
| 非 PK 段 | 保存后被写成 PK | 进入左右模式时提示；面板常驻计数 |
| 22050 Hz | 保存后变 20000 Hz | 点模型上界 20 kHz；文档写明 |
| 超过 31 个点 | Peace 界面显示不全 | 状态栏常驻提示；声音与 `peace.txt` 完整，不静默丢点 |
| 编辑态不实时 | 用户以为没生效 | 已改为试听：改一下就写 `peace.txt`，顶部常驻「试听中」 |
| 写入被拒（权限 / 沙箱） | 保存失败 | 明确报错；开发时用 `run.cmd` 从 `%LOCALAPPDATA%` 启动 |
| 频谱占 CPU | 界面卡顿 | 后台线程、降采样、可关闭 |
