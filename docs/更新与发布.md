# 更新与发布

## 一条命令发布

```
release.cmd          ← 双击，按提示输入版本号（不用输 v）
release.cmd 1.0.2    ← 或者带参数直接跑
```

它会做五件事：

1. 校验版本号，并写进 [PeaceWpf.csproj](../src/PeaceWpf/PeaceWpf.csproj) 的 `<Version>`；
2. 清掉旧的 `dist\EasyEQ`、`dist\EasyEQ.7z`、`dist\EasyEQ.zip`；
3. 自包含发布 win-x64（Release）；
4. 打 `dist\EasyEQ.7z`（手动下载用）和 `dist\EasyEQ.zip`（软件内更新用）；
5. 核对编译出来的 exe 文件版本和输入一致，对不上就报错、不上传。

它**不**做：git 提交、EasyEQ 备份、上传 GitHub。

跑完之后手动做：

1. GitHub → Releases → Draft a new release；
2. Tag 和标题都用 `V1.0.2` 这种格式；
3. 两个文件都上传，`EasyEQ.zip` 的名字一个字都不能改；
4. 把 csproj 的版本号改动提交（`git add src/PeaceWpf/PeaceWpf.csproj`）。

脚本是纯 ASCII 英文提示：cmd 在中文代码页下解析 UTF-8 批处理文件会乱码，中文只放在这份文档里。

它调用了两个辅助脚本，改它们的时候注意两件事：

- [set-version.ps1](../tools/set-version.ps1) 必须带 UTF-8 BOM。Windows PowerShell 5.1 会把无 BOM 的文件当 ANSI 读，
  csproj 里的中文注释会被读成乱码再写回去。
- [release.cmd](../release.cmd) 必须保持 CRLF 换行。LF-only 的批处理在 cmd 里会丢字符、把括号块拆坏。

## 软件内更新是怎么实现的

用户在「设置 → 关于软件 → 检查更新」点一下之后：

```
UpdateChecker.CheckAsync         读 GitHub 的 latest release，比对版本，找名为 EasyEQ.zip 的资产
        │
        ▼
UpdateInstaller.DownloadAsync    下载到 %TEMP%\EasyEQ-update\<版本>\EasyEQ.zip
        │
        ▼
UpdateInstaller.Extract          用 .NET 的 ZipFile 解压到同目录 files\，检查里面有 EasyEQ.exe
        │
        ▼
MainWindow.ConfirmBeforeUpdate   先问保存：有未保存的改动，用户可能选「继续编辑」，那就到此为止
        │
        ▼
UpdateInstaller.TryLaunchApplier 启动 files\EasyEQ.exe --apply-update <安装目录> <当前pid> <files目录>
        │
        ▼
MainWindow.QuitForUpdate         跳过「收托盘还是退出」，关掉子窗口，主窗口关闭，进程结束
        │
        ▼
新 exe 的 App.OnStartup          在单实例锁之前拦下 --apply-update，走更新器模式
        │
        ▼
UpdateInstaller.RunApplyUpdate   等旧进程退出 → robocopy /MIR 覆盖安装目录 → 启动新版本
```

几个关键设计：

- **更新器就是新版本的 exe 自己**，不是 bat 或 ps1。安装路径带中文和空格时批处理容易翻车，
  PowerShell 又可能被执行策略拦住；新版本本来就是完整可运行的程序，让它干这件事最稳，也不用额外依赖解压器。
- **`--apply-update` 必须在单实例锁之前处理**，否则会被当成「第二个实例」直接赶走
  （见 [App.xaml.cs](../src/PeaceWpf/App.xaml.cs)）。
- **先问保存，再启动更新器**。反过来的话，用户在确认框里选「继续编辑」，更新器会白等两分钟。
- **数据不在安装目录**：配置和预设都在 `%LOCALAPPDATA%\EasyEQ`，覆盖程序目录不会丢设置。
- **下载地址只认 GitHub 域名**（`UpdateInstaller.IsTrustedDownloadUrl`），防止接口被篡改后把程序引到别处执行 exe。

## 要注意什么

### 发布的时候

1. **`EasyEQ.zip` 的名字不能变。** 程序按 `UpdateChecker.UpdateAssetName` 找资产，名字不对就只跳发布页，
   不会报错——这是最容易踩的坑。
2. **zip 根目录必须直接是 `EasyEQ.exe`**，不能套一层文件夹。`release.cmd` 已经保证这一点。
3. **tag 要是 `V1.0.1` 这种能被解析成数字的格式。** `NormalizeVersion` 只认数字和点。
4. **别发成 prerelease 或 draft。** 程序读的是 `releases/latest`，这两种都不算。
5. **7z 和 zip 都传。** 7z 给手动下载的人，zip 给自动更新。
6. **版本号以 csproj 为准**，`release.cmd` 会自动写；手改的话记得只改这一处。

### 用户那边

1. **安装目录必须可写。** 放在 `Program Files` 下时，普通权限的更新器覆盖不了 exe，更新会失败
   （日志在 `%TEMP%\EasyEQ-update\apply-error.log`）。绿色版放在用户目录下没有这个问题。
2. **杀毒软件可能拦覆盖 exe**，表现为更新后版本没变、日志里有 robocopy 失败。
3. **1.0.0 及更早的版本没有更新器**，它们点「检查更新」只会打开网页。自动更新从 1.0.1 开始生效，
   所以第一次升级到 1.0.1 仍然要手动装一次。
4. 更新会先退出程序；有未保存改动时会先问保存，不会带着草稿重启。

### 改代码的时候

1. 改更新包名字时，要同时改 `UpdateChecker.UpdateAssetName`、`UpdateInstaller.PackageFileName`
   和发布脚本，三处必须一致。
2. 不要往安装目录里放用户数据（预设、配置、缓存）——更新用 `robocopy /MIR` 覆盖，
   源目录里没有的文件会被删掉。用户数据一律放 `%LOCALAPPDATA%\EasyEQ`。
3. 改 `RunApplyUpdate` 之后一定要做一次本地模拟替换，见下一节。

## 本地模拟一次更新

不用等 GitHub，能直接验证替换逻辑：

```powershell
# 1. 准备「旧版本目录」和「新版本目录」（newfiles 里随便加个标记文件）
Copy-Item -Recurse src\PeaceWpf\bin\Debug\net10.0-windows dist\update-test\old
Copy-Item -Recurse dist\update-test\old dist\update-test\newfiles
"1.0.1" | Out-File dist\update-test\newfiles\version-marker.txt

# 2. 启动旧版本，记下 pid
Start-Process dist\update-test\old\EasyEQ.exe

# 3. 用新版本 exe 当更新器，pid 传 0 表示不等待
Start-Process dist\update-test\newfiles\EasyEQ.exe `
  -ArgumentList '--apply-update', "$PWD\dist\update-test\old", 0, "$PWD\dist\update-test\newfiles"

# 4. 等几秒，检查 marker 是否被复制进 old，并且新进程从 old 启动
Test-Path dist\update-test\old\version-marker.txt
```

注意：在 PowerShell 里用 `Start-Process` 启动 GUI 程序时，如果调用方是脚本，别让它继承输出管道，
否则脚本会一直挂着。用 `cmd /c start ""` 也行。

## 常见问题

| 现象 | 原因 |
|---|---|
| 检查更新说「还没有线上版本」 | 还没发 Release，或者发成了 draft / prerelease |
| 发现新版本但只打开网页 | Release 里没有 `EasyEQ.zip`，或名字不对 |
| 下载 404 | 资产名字不对，或者 tag 和资产不匹配 |
| 更新后版本没变 | 覆盖失败，看 `%TEMP%\EasyEQ-update\apply-error.log` |
| 提示版本对不上 | csproj 的 `<Version>` 和实际构建不一致，重新跑 `release.cmd` |
