# 配置目录权限：先分因，再修

EqualizerAPO 装在 `Program Files` 下时，`config` 目录默认只有管理员能写。保存失败时最没用的一句提示是「请以管理员身份运行」——因为它可能是错的。这份文档说明程序怎么判断、判断出什么、以及每一类原因该动哪里。

## 为什么不能只有一个「一键授权」

`Program Files\EqualizerAPO\config` 写不进去，至少七种原因，只有一种跟 ACL 有关：

| 原因 | 现象 | 加权限有用吗 |
|---|---|---|
| 程序跑在低完整性下 | 自称管理员，写测试仍被拒 | **没用**，要降目录的完整性标签 |
| 没提权 | 普通用户跑，目录只给管理员 | 有用，但方式是重新以管理员启动 |
| 文件带只读位 | `peace.txt` / `.peace` 有 ReadOnly 属性 | 没用，要清属性 |
| 文件被占着 | 别的程序以写方式打开着 `peace.txt` | 没用，要关掉那个程序 |
| Defender 受控文件夹访问 | 提了权也拒，日志里有拦截记录 | 没用，要改安全中心设置 |
| ACL 缺写权限 | 低完整性也排除了、没只读、没占用 | 有用，这一条才是加 ACE |
| 目录不存在 | 装到别的地方去了 | 没关系，要改配置目录 |

所以界面上不叫「一键授权」，叫「检查权限」：先出结论，再给动作。

## 低完整性：ACL 之上还有一层

这一条值得单独写，因为它把前面所有办法都废掉了。

Windows 除了 ACL，还有**完整性级别（integrity level）**：低（0x1000）/ 中（0x2000）/ 高（0x3000）/ 系统（0x4000）。默认情况下，`Program Files` 下的东西是「中」，**低完整性进程写不了「中」的对象，这一层在 ACL 之前判定**。

所以会出现这种局面：

- 目录 ACL 里 `BUILTIN\Users:(OI)(CI)(F)`，写得清清楚楚；
- 程序自己报「当前进程：管理员」，因为 Administrators 组确实在令牌里；
- 但它的令牌是「低」，写测试依然 `UnauthorizedAccessException`；
- 加 ACE、点授权、重启电脑，全都没用。

### 怎么变成低完整性的

这台机器上 `EnableLUA = 0`（UAC 被关掉）。UAC 关闭时，Windows **忽略 exe manifest 里的 `requireAdministrator`**，进程直接沿用启动者的完整性级别。于是：

- 如果启动链上游是个低完整性上下文，程序就是低的；
- `runas` 动词在这时候也不提升完整性——它只是用同一个令牌再来一次，最多弹一次没意义的确认。

程序本身没法把自己从「低」抬到「高」：`SetTokenInformation` 改自己的完整性需要特权，低完整性令牌没有。

### 解法：把目标目录的标签降下来

既然抬不动进程，就降目录：

```
icacls "C:\Program Files\EqualizerAPO\config" /setintegritylevel (OI)(CI)L
```

这条要**管理员**跑一次（改 SACL 需要 `SeSecurityPrivilege`，低完整性没有——所以程序自己执行不了，诊断窗口只会把命令复制到剪贴板）。

`(OI)(CI)` 让它继承到目录里已有的和以后新建的对象。跑完之后，低完整性进程写这个目录就通了，不需要每次提权。

改造前后（同一台机器、同一个低完整性进程）：

```
# 之前
写测试：失败 —— UnauthorizedAccessException: Access to the path '...' is denied.

# 之后
完整性级别：低（Low）。
写测试：通过（在目录里建了个临时文件又删掉）。
```

### 代价和退路

- 影响范围只有这一个目录。它本来就要给 Peace / EqualizerAPO 这类工具写，降标签不改变「谁能写」的 ACL 结论，只是让低完整性进程也能进来。
- 不碰 `Program Files` 本身，也不动任何 ACL。
- 退回去：

```
icacls "C:\Program Files\EqualizerAPO\config" /setintegritylevel (OI)(CI)M
```

- 重装 EqualizerAPO 时，安装程序可能把这个标签重置回「中」。到时候重新跑一次降标签的命令即可。

## 判定顺序

`ConfigPermission.Diagnose` 按这个顺序走，前面命中就不往下看：

1. 目录在不在
2. 只读位（`peace.txt`、`config.txt`、目录里所有 `.peace`）
3. 占用（以 `FileShare.Read` 打开目标文件；允许别人读，只挡「别人正在写」）
4. 写测试（目录里建一个临时文件再删掉）
5. **写不进去才查完整性级别**：低 → 归 `LowIntegrity`，到此为止
6. 是不是管理员
7. Defender 受控文件夹访问（读注册表 `EnableControlledFolderAccess`，1 开 / 2 只审计 / 0 关）
8. 都不是 → 归为 ACL 缺写权限

第 5 步排在写测试之后是有意的：低完整性进程写 `%TEMP%` 是通的，一上来就报「低完整性」会误伤那些本来就能写的目录。

第 3 步用 `FileShare.Read` 而不是 `FileShare.None`，也是有意：EqualizerAPO 会一直读 `peace.txt`，独占打开会把正常读取误判成占用，还会卡引擎一下。

## 修复动作

| 诊断 | 修什么 |
|---|---|
| 低完整性 | 程序自己改不了；把 `icacls ... /setintegritylevel (OI)(CI)L` 复制到剪贴板，让用户用管理员跑一次 |
| 只读位 | 清掉这些文件的 ReadOnly 属性，再测一次 |
| 占用 | 我们清不了别人手里的句柄；重测一次看对方是否已放手 |
| 没提权 | 只能提示重新以管理员启动——程序改不了自己的令牌 |
| 受控文件夹访问 | 不改系统开关，只给出去安全中心的操作路径 |
| ACL | `icacls <目录> /grant *S-1-5-32-545:(OI)(CI)M /T /C` |

两条细节：

- 改 ACL 用 SID `S-1-5-32-545` 而不是「Users」，避免系统语言不同时组名对不上。
- 改 ACL 之前先跑一次 `icacls <目录>`，把输出存成 `%LOCALAPPDATA%\PeaceWpf\acl-<时间>.txt`；改完不看 `icacls` 的返回码，直接用真实写测试验证。

修复动作跑在后台线程（`Task.Run`）。这一条不是洁癖：`icacls /T` 在大目录上会慢，走 UI 线程五秒没响应就被 Windows 判 AppHang 直接杀掉——这个坑真踩过。

## 修完之后

修成功了才回主窗口重测可写状态（`MainViewModel.RecheckConfigWritable`）。只重测，不重新载入预设——修个权限不该把正在编的曲线冲掉。

顶栏那句红字是**启动时算一次**的，不会自己刷新；目录改好之后要么重启程序，要么在诊断窗口点一次「重新诊断」让它触发重测。

## 命令行入口

自测程序带一个同样的诊断入口，不用开界面就能问：

```powershell
dotnet run --project tests\PeaceWpf.Core.SelfTest -c Debug -- --diagnose "C:\Program Files\EqualizerAPO\config"
```

输出跟窗口里一致：结论、下一步、明细。可写时退出码 0，不可写时 1。

注意：在 DSH 会话里用 `ops_bash` 跑 `dotnet`，那个子进程通常是**低完整性**（`ops_bash` 和 `pwsh` 工具本身是高的，它们拉起的 .NET 子进程不是）。所以这条命令在这种环境里会如实报 `LowIntegrity`——那不是误报，它确实写不进去。判断机器真实状态看两处：程序自己的 `startup-report.txt` 里的 `configWritable`，或者用高完整性 shell 直接写一个临时文件试试。

## 一次真实的「滑块没反应」（2026-10-24）

现象：增益和均衡拖得动、数字也变，`peace.txt` 一个字不改，声音当然不变。状态栏里其实写着
`写 peace.txt 失败：Access to the path '...\PeaceWpf\peace.txt.bak' is denied.`

两个原因叠在一起：

1. **构建输出目录被打了「低」完整性标签**：`bin\Debug\net10.0-windows` 是低，
   里面的 `PeaceWpf.exe` 也是低。exe 的标签会跟着进程走——从资源管理器、从命令行、从哪启动都一样低。
   低进程写不了「中」的 `peace.txt.bak` 和 `peace.txt`，ACL 给得再宽也没用。
2. **备份失败把整次写入带走了**：即时保存先 `File.Copy` 备份，备份抛 `UnauthorizedAccessException`
   就直接进了错误分支，真正要写的 `peace.txt` 没轮到。备份是保险，不该是前置条件——这一条已经改成
   best-effort（`BackupPeace` 吞掉 IO/权限异常），保存不再因为 `.bak` 失败而作废。

查这件事的两条命令（管理员 PowerShell）：

```powershell
# 进程到底在哪个完整性级别
tools\integrity.ps1          # 看 PeaceWpf 是 Low / Medium / High
# exe 和目录被谁打了标签
tools\label.ps1              # 看 label RID=1 就是低

# 恢复正常（把 exe 目录、AppData、config 目录都归到「中」）
icacls "<exe 目录>" /setintegritylevel (OI)(CI)M /T /C
```

注意：给 **exe 所在目录**降标签（`...L`）等于让这个程序永远以低完整性运行，是这次故障的源头；
只有给 **目标目录**（config）降标签才是文档前面说的那种取舍。

## 边界

- 不碰 Defender 的设置。改系统安全开关不该由这个程序做。
- 不给「Everyone 完全控制」这种授法，只加 Users 的修改权限。
- 不自己提权：低完整性时只复制命令，不弹 UAC；UAC 关掉的机器上 `runas` 本来也提不动。
- 目录不存在时不猜位置，去设置里指。
