# 自动风味：方向目标的来源台账

一句话：八条方向的目标曲线不再手写，全部由公开配方换算得出。每格数值都能追到下面的原始 dB 表；
哪几条是原样引用、哪几条是推出来的，这里逐条写明。

代码落点：

| 东西 | 位置 |
|---|---|
| 来源表与换算 | `src/PeaceWpf.Core/AutoFlavor/AutoFlavorProfileSource.cs` |
| 方向表（只保留上下限与文案） | `src/PeaceWpf.Core/AutoFlavor/AutoFlavorDirection.cs` |
| 自测（目标必须等于来源换算值） | `tests/PeaceWpf.Core.SelfTest/Program.cs` 的 S18 段 |

---

## 1. 为什么换

旧表是手写的「各类型音乐普遍怎么调」，代码注释自己写着「不是测量真值」。它的问题不是数字难听，
而是改不动：任何一格都说不出依据，也没法验证。现在每一格都能追到一份公开写了 dB 的配方。

---

## 2. 四个参考源，各自能拿到什么

| 来源 | 拿到了什么 | 用没用 |
|---|---|---|
| [SnipSound](https://snipsound.com/tools/audio-equalizer) | **完整**：10 段（31/62/125/250/500/1k/2k/4k/8k/16k）逐段 dB，Pop / Rock / Hip-Hop / Classical / Vocal Boost / Podcast 六条全给了 | **是**，六条原样引用 |
| [ToolChamp](https://toolchamp.app/tool/audio-equalizer) | 只公开了 Podcast 一条的数值（32 −4、64 −3、500 +4、1k +6），其余 11 个预设只有名字；但明确写了 32 Hz 低架、16 kHz 高架、中间八段峰值 | 否（数值不全）；其「两端架式 + 中间峰值」的布局与本项目九条风味一致，可作为布局佐证 |
| EditClips | 页面正文抓不到（每次都被超长导航挤掉），只有站点描述 | 否 |
| [SoundYak](https://soundyak.com/effects/equalizer/) | 8 段 EQ，首页可开，工具页抓不到正文 | 否 |
| [AlexWabita/equalizer-apo-profiles](https://github.com/AlexWabita/equalizer-apo-profiles) | 28 套（14 场景 + 14 曲风），但 README **只有文字描述、没有逐段 dB** | 否，理由见下 |

### 为什么不用那个 GitHub APO 仓库

它有 28 套配方，看着最像「28+ 个 EQ 配置」，但两个硬问题：

1. **没有数值。** README 里每套只有一句「Deep bass, punchy beats」这类描述，`config_*.txt` 才是真数据，而 README 本身不展开。
2. **用途对不上。** 它自己写明是给**室内低音炮系统**调的，还专门给了换算：
   - 「For Headphones: Reduce all bass gains by 3-4 dB」
   - 「For Small Speakers (No Subwoofer): Reduce sub-bass (20-60 Hz) gains significantly, Focus on mid-bass (80-200 Hz)」

照搬等于把低音炮的量搬到耳机上。它真正有用的是频率区间的含义，这套划分和 SnipSound 各配方的走向一致，可以互相印证：

| 区间 | 原文含义 |
|---|---|
| 20–60 Hz | 更多是体感不是听感 |
| 60–250 Hz | 厚度与温暖 |
| 250–2 kHz | 人声与多数乐器 |
| 2–5 kHz | 清晰度与细节 |
| 5–16 kHz | 光泽与空气感 |

---

## 3. 换算规则

来源是 10 段非等距网格，我们的九条风味落在它们中间，所以在**对数频率上线性插值**，
和 `TargetAt` 用的是同一套规则；两端不外推：

- 80 Hz 在 62 与 125 之间插
- 17000 Hz 超过 16000，取端点值
- 原始配方没提到的段补 0 dB

九条风味的中心频率：80 / 220 / 700 / 1800 / 2500 / 4500 / 7000 / 12000 / 17000 Hz。

## 4. 逐条台账

「原样」= 直接引用来源，「派生」= 由两条来源按固定权重合成，权重写在下面。

### 竞技定位 —— 派生

来源配方：[SnipSound · Podcast](https://snipsound.com/tools/audio-equalizer)
原始：31 −6、62 −3、250 −2、4k +3（原文称「HPF substitute + mud cut + intelligibility」）

**唯一改动**：把 4 kHz 的 +3 复制一份到 2 kHz。原因：Podcast 抬的是语音清晰度，
落点在 4 kHz；游戏脚步的定位区间在 2.5 kHz 附近，原样照搬会让枪声（4.5 kHz）比脚步抬得更多，
和「脚步是定位线索」正好相反。

| −1.91 | −1.63 | 0 | 2.54 | 3.00 | 2.49 | 0 | 0 | 0 |

### 男声民谣 —— 派生

0.65 × Classical + 0.35 × Vocal Boost。
保留古典的温和底子，借用 Vocal 的 2–4 kHz 让人声清楚。

需要说明的是：**两个来源都没有在 700 Hz 抬升**（业界普遍把 700 Hz 当「盒子音」来处理）。
所以这条的男声中心只有 +0.33 —— 男声靠的是 1–2 kHz 的清晰度，不是 700 Hz 的厚度。旧文案写「男声暖厚」，已改。

## 5. 两处不是来源、是判断的地方

诚实起见单独列出来：

1. **齿音（7000）和尖啸（17000）的目标压回不抬。**
   来源配方在 8k/16k 的提升本意是空气感，但落在这两条风味上就是「抬刺耳」。这两条的增益上限本来就是 0，
   目标若为正会被上限吃掉、白算一遍。所以 `TargetsFor` 里把这两格夹到 `≤ 0`。
   代价：微笑曲线的高频那一截在齿音带上不体现（空气感仍由 12000 那条承担）。

2. **竞技定位把 4 kHz 的抬升复制到 2 kHz。**
   理由见上面那条。

## 6. 量级变了，这是预期的

新目标的起伏普遍在 ±0.3 ~ ±3.8 dB，旧表是 ±2 ~ ±7 dB。加上两个既有机制，实际动作会更轻：

- `MinPeakDb = 1.5`：目标与实测差不到 1.5 dB 就不动这一条
- `GainScale = 强度`：实际增益是差值 × 强度，默认强度 0.6 只有六成

原配方本来就是「对已混音的音乐再调味」的量级，不是「把缺的补足」的量级。
想要更明显就往强度滑杆推——那是这条管线本来就留的放大手段，不需要改表。

---

## 7. 怎么改

1. 改 `AutoFlavorProfileSource.cs` 里的某条来源（`GridDb` 的 10 个值）。
2. 跑 `dotnet run --project tests/PeaceWpf.Core.SelfTest`。
3. 目标值会自动跟着变（`TargetDb` 就是换算出来的），不需要手改方向表。
4. 自测里有一条「目标就是来源换算值」，它保证两边不会漂移。

新增一个方向时，只需要在 `For()` 里指定来源、在 `AutoFlavorDirection.cs` 里给上下限和文案。
