# Peace 功能清单（供取舍）

按模块编号。每个模块标三件事：后端协议覆盖度、WPF 要做的量、我的建议。

协议的三种状态：

- **能直接接**：现有 `WM_APP` 消息已经覆盖，WPF 接上就行
- **要自己写**：后端不提供，WPF 独立实现（数据由 WPF 自己管）
- **要改后端**：需要给 Peace.au3 加新消息，或改它的行为

## M2 预设管理

Peace 的日常用法几乎都绕着这个转。

| 项 | 协议 | 量 |
|---|---|---|
| 预设列表、点一下切换 | 能直接接，`WM_APP+2` / `WM_COPYDATA` | 中 |
| 保存当前、另存为、重命名、删除 | 部分能接，另存有 `WM_COPYDATA` case 3，删除要自己删文件 | 中 |
| 预设备注、网页链接、ID | 要自己读写 `.peace` 的 General 段 | 中 |
| 预设热键 | 要改后端（热键在 Peace 里注册） | 中 |
| 启动时指定预设 | 能直接接，命令行参数 | 小 |

建议：必做。没有它这程序不能日常用。

**现状（2026-10-25）：重命名 / 删除做了，外加复制和手动排序。** 「左右」「低音」两个预设下拉里，
每一项右侧有一条 `⋮⋮` 抓手：按住上下拖就能改顺序，顺序存在 `ui-state.json` 的 `presetOrder` 里，
下次开程序还是这个顺序。右键任意一项（下拉收着时右键下拉本身也行）弹出的菜单是
`重命名… / 复制 / 删除…`：重命名改的是磁盘上的 `.peace` 文件名，正在用的那一层会跟着改名；
复制会新写一份文件并插在原文件后面；删除要先确认，正在用的那一条会先切到别的预设再删，
这层还有没保存的改动时不让删。细节见 [预设下拉.md](预设下拉.md)。

## M9 AutoEQ 导入

从 AutoEQ 的耳机数据库里选型号，一键生成目标曲线。

| 项 | 协议 | 量 |
|---|---|---|
| 选型号、拉曲线、生成 EQ | 要自己写（数据可以复用 `AutoEQCompressedVersion5.txt` 的索引） | 中 |
| 内置数据包 | 可以直接用现成的 AutoEQ 压缩包 | 小 |

建议：如果你换耳机频繁，很值；否则一般。

**现状（2026-10-24）：已做。** 主界面多了 `预设EQ` 按钮：四个结果库、按型号/佩戴方式/测量者搜索、
参数 EQ 与固定频带 EQ 一键套到「左右」层（架式滤波器一路写进 `.peace` 和 `peace.txt`），
图形 EQ 只能看/复制命令。数据来自 Peace 自带的 7z，解开后放在 `src/PeaceWpf/AutoEqData/`。
型号列表左侧会带品牌图标：矢量标记取自 Simple Icons（CC0），字标取自维基共享资源（已统一成白色单色），
按型号名开头的品牌匹配，认不出的牌子不显示图标、文字照常顶格。覆盖有限（8186 条里约 345 条、
46 个品牌），小厂和国内牌子大多没有公开矢量，不拿自制的占位图凑数。
细节见 [AutoEQ.md](AutoEQ.md)。

## M9.5 自动EQ（扫频校准）

不查表，当场测：放一段扫频，用麦克风听回来，算出要补的 EQ。

| 项 | 协议 | 量 |
|---|---|---|
| 扫频播放 + 麦克风采集 | 要自己写（WASAPI 播放与录音，NAudio） | 中 |
| 音频分析（切段、电平、归一化） | 要自己写（纯数学，可自测） | 中 |
| 目标曲线（平直 / 哈曼） | 要自己写 | 小 |
| 拟合 EQ（多段叠加的补偿） | 要自己写（线性方程组） | 中 |

**现状（2026-10-24）：已做。** 主界面 `预设EQ` 右边多了 `自动EQ` 按钮：先问平直还是哈曼，
然后 61 点步进正弦扫频（20 Hz–20 kHz，23 秒）、按能量切段、按 1 kHz 归一化，
19 段峰值滤波器解线性系统拟合，套到「左右」层。测量期间临时把 `peace.txt` 写平直，测完还原。
细节与限制见 [自动EQ.md](自动EQ.md)。

## 我的排序建议

第一批（做成能日常用）：M2 预设 → M3 设备与声道组合 → M1 补齐（类型/图形EQ/段数）→ M12 托盘与热键。

第二批（调音体验）：M7 曲线叠加 → M4 低音高音 → M12 峰值表 → M13 主题与中文。

第三批（看你实际用法）：M5 空间效果、M6 路由、M9 AutoEQ、M11 MIDI。

基本可以放弃：M8 听力测试、皮肤包、启动密码。

---

## 协议之外的一条捷径

Peace 的设置存在 ini 里（`peace.ini` 之类的 `$IniFile`）。WPF 可以直接读写同一份 ini 来共享设置，不需要给它加新消息。这条对 M3 的命名、M4 的平衡、M14 的开关都有用，代价是要小心两边同时写。

需要新协议才能做的，其实只有：延迟、路由/静音矩阵、环绕细节、上混细节、平衡、热键、听力测试。其余都能绕过去。
