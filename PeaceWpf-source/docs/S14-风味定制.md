# S14 风味定制：独立叠加层

日期：2026-10-26

## 一句话结论

曲线编辑器右边多了一组「风味」：下拉选一种声音类型，点「增强 / 减弱」各 ±1 dB。
它是**叠加层**，不是曲线内容——八条固定滤波器只写进 `peace.txt`，不写进 `.peace`，
按「左右」预设各存一份，存在 `ui-state.json` 里。

## 为什么是独立层，而不是往曲线上加点

试过的一种设计是「点一下就在曲线上加一个点」。放弃它的理由不是手感，是结构：

| 需求 | 加点方案 | 独立层方案 |
|---|---|---|
| 风味跟着「左右」预设走 | 点会写进 `.peace`，和预设的曲线混在一起，分不开 | 存在 `ui-state.json` 的 `mainFlavors` 里，按文件名分 |
| 不能增删数量 | 点可以被删掉、被拖走，数量守不住 | 八条由表决定，界面上没有删除入口 |
| 不是调曲线，是叠加 | 用户会以为改的是预设本身 | 只进 `peace.txt`，`.peace` 一个字节都不动 |
| 单独显示 | 只能混在主曲线里 | 曲线图上多画一条叠加量曲线 + 彩色手柄 |

同时保留了「有过渡」的听感：每条风味是一条真实滤波器，钟形/坡形的边界由 Q 决定，
不需要额外写渐变算法。

## 八条类型

按频率升序，也是下拉顺序；颜色按彩虹顺序排（红→橙→黄→黄绿→绿→青→蓝→紫）。
配色在 `src/PeaceWpf/Theme/TonePalette.cs`，下拉文字、曲线手柄、每条风味自己的那条曲线共用这一份。

| 键 | 名称 | Lucide 图标 | 颜色 | 覆盖 | 默认频率 | 类型 | 默认 Q |
|---|---|---|---|---|---|---|---|
| boom | 爆炸/载具 | `bomb` | `#F4585C` 红 | 30–150 Hz | 80 Hz | LS 低架 | 0.7 |
| voiceM | 男声 | `mars` | `#F78E3D` 橙 | 300–1200 Hz | 700 Hz | PK | 0.9 |
| voiceF | 女声 | `venus` | `#F6C945` 黄 | 1–3.5 kHz | 1.8 kHz | PK | 0.9 |
| step | 脚步 | `footprints` | `#A8D45A` 黄绿 | 1.5–4 kHz | 2.5 kHz | PK | 1.0 |
| gun | 枪声 | `crosshair` | `#5CC46A` 绿 | 2–7 kHz | 4 kHz | PK | 1.1 |
| mech | 换弹/机械 | `wrench` | `#3FC9C1` 青 | 3–9 kHz | 5.5 kHz | PK | 1.3 |
| sibil | 齿音 | `wind` | `#4A9DF0` 蓝 | 5–10 kHz | 7 kHz | PK | 1.6 |
| air | 空间/细节 | `sparkles` | `#A46BE0` 紫 | 10–16 kHz | 12 kHz | HS 高架 | 0.7 |

图标来自开源图标库 **Lucide**（<https://lucide.dev>，ISC 许可；`crosshair` 沿用自 Feather，MIT）。
仓库里只保留 24×24 视框的几何路径（`src/PeaceWpf/Theme/FlavorIcons.cs`），不依赖图标字体，
颜色和描边粗细由代码给；许可原文见 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)。

最外侧两条用架式，因为再往外没有东西可以「过渡」；中间六条是峰值。
频点是听感起点值，不是实验室测量——Q 用户能自己滚轮改，所以不必抠到工程值。

### 补充过、但没收的候选

| 候选 | 频段 | 没收的原因 |
|---|---|---|
| UI 提示音（命中标记、技能就绪） | 1–3 kHz | 和女声中心几乎重合，选「女声」一样能调 |
| 技能音效（能量、魔法） | 2–8 kHz | 横跨枪声/换弹/齿音三段，单独一条会重复 |
| 环境声（风、雨底噪） | 200 Hz–2 kHz | 宽带、无明确中心；需要时用宽钟手拖更准 |
| 水声/水下 | 50–500 Hz + 2–6 kHz | 太偏，只有水下关卡用得上 |
| 背景音乐 | 全频 | 不是「一个频段」的事，属于整体风格 |

## 怎么用

| 操作 | 效果 |
|---|---|
| 下拉 | 选类型；每项前面是它的图标，字是它自己的颜色。**「左右」和「低音」两种编辑态都会出现**；列表一律向上弹（它固定在底部工具条上，向下会顶出屏幕） |
| 曲线上拖手柄 | 横向改频率（夹在该类型的覆盖范围内）、纵向改增益（夹在 ±30）；两个方向都跟手 |
| 手柄上滚轮 | 改 Q（×1.15 每格），夹在 0.1–30 |
| 右键手柄 | 把这一条的增益归零（频率和 Q 保留），算一步撤回——不是删除 |
| 点曲线空白 | 仍是建 EQ 点，碰不到风味 |

没有「增强 / 减弱」按钮了：增益就是纵向拖，跟 EQ 点的肌肉记忆一致。

图上的关系：**每条风味在曲线图上各画一条自己的曲线，颜色和下拉的名称一致，选中的那条加粗**；
它们画在正在编辑的那条曲线下面（左右/低音都一样），那条曲线还带一圈暗色描边，
所以风味从它下面穿过去也不会把它盖住；手柄和图标在最上面一层。
手柄是自己的颜色，圆点上下的图标就是下拉里那个图标——抬的时候在控制点上方，削的时候在下方。

**0 dB 的风味不画**（曲线、手柄、图标都没有——它没在改变声音）。
例外只在「左右」编辑态：下拉里正选着的那一条即使 0 dB 也画出来，否则就没有东西可以往上拖。
退出编辑后这个例外失效，0 dB 的一律隐藏；右键归零也会立刻让它消失。

## 存储与合并

- `ui-state.json` 新增 `mainFlavors`：`{ "EsportsMain.peace": [ {key, frequencyHz, gainDb, quality, filterType} ×8 ] }`。
- 读取时按表重建：缺的补默认、多的丢掉、越界的夹回来——旧档（没有这个字段）读进来就是八条全平。
- 合并入口只有一条：`EqLayerSet.TryMerge(includeBass, flavor, out merged, out error)`，
  把风味的非 0 dB 条目追加到主层 + 低音层后面统一排序。7 个调用点全部吃这一份。
- 保存：`.peace` 只写两层曲线；`peace.txt` 写「两层 + 风味」的合并结果；风味本身写进 `ui-state.json`。
- 切预设：旧的先记回 `mainFlavors`，再读新的，然后立刻重写 `peace.txt`。

## 和曲线共用一条草稿（保存 / 取消 / 撤回）

风味的改动走的是和曲线同一个 `EqDraft`：草稿状态是「点列表 + 风味」两件一起
（`EditSnapshot`），所以：

| 动作 | 结果 |
|---|---|
| 拖风味手柄 / 滚轮改 Q | 立刻算「还没保存」，保存 / 取消按钮出现，声音当场变 |
| Ctrl+Z | 一步退回一次拖动或一次滚轮，点列表和风味一起退 |
| Ctrl+Y | 重做 |
| 保存 | 曲线写回 `.peace`，风味写进 `ui-state.json`，两者成为新的基线 |
| 取消 | 曲线和风味一起退回上次保存那份，声音跟着退回去 |

一次拖动只算一步：拖动过程只 `PreviewFlavors`，松手才 `Commit`。

## 一个容易被漏掉的坑：取消编辑

「取消」会把 `peace.txt` 还原成试听前的原文，而原文里没有风味——照原样还原，声音里的风味会一起消失。
所以 `RestorePreviewAsync` 还原成功之后补一句：风味不是全平时，用「已保存的两层 + 风味」再写一遍。
写的时候 `announce: false`，不覆盖「已放弃改动」那句状态栏。

## 与撤回栈的关系

风味和曲线共用一条 50 步的撤回栈，顺序就是操作顺序：拖一下风味、再拖一个 EQ 点，
Ctrl+Z 先退点、再退风味。低音层只有点，风味那一半一直是默认值，不影响它自己的撤回。

两种编辑态都能调风味，所以 Ctrl+Z 跟着「最后改过的那一层」走：编低音时顺手拉了风味，
撤回退的是风味；接着拖低音的点，撤回就退点。按钮能不能按也按同一层判断。
