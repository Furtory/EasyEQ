# S0–S4 交付说明（保存改为前端写配置文件）

日期：2026-10-24
依据：`执行计划.md` S0–S4，以及三次修订：三模式语义、保存只在前端完成、两层各自绑定 Peace 预设。

## 一句话结论

保存不再逐段遥控后端（那会让 Peace 重建界面、很慢），而是把两层合并后的 EQ 直接写成 EqualizerAPO 的 `peace.txt`。编辑只改内存，保存才写文件，取消完全回滚，撤回 50 步。Peace 只负责被收起来，不参与读写。

## 三个模式

| 模式 | 界面上是什么 | 保存时落到哪 |
|---|---|---|
| 均衡 | 一条 -1…1 的滑块 | 写进 `peace.txt` 的 `Channel: L/R` + `Preamp` |
| 左右 | 主 EQ 曲线 + 右侧预设下拉 | 写回选中的 `.peace`（默认 `EsportsMain.peace`） |
| 低音 | 第二条 EQ 曲线 + 右侧预设下拉 + “叠加”开关 | 写回选中的 `.peace`（默认 `EsportsBass.peace`），开关关着就不参与合并 |

两个下拉栏列出 config 目录里所有的 `.peace`。切换时当前层先写回旧文件，再载入新文件；叠加开关一改就立即保存，不弹询问。保存的完整动作是：主预设 + 低音预设 + 合并出的 `peace.txt`。

曲线区在三个模式下都显示：当前层亮色、另一层灰色虚线做参考。全灭时显示合并后的“实际声音”。

## 保存流程

1. 合并：主层全部点 + 低音层中间点（“非端点、增益不为 0”）+ 低音层端点并进主层同名端点（同频只留一个滤波器），按频率排序；超过 31 个点拒绝保存并说明要删几个。
2. 生成文本：`Device`、`Preamp`、可选的左右平衡（`Channel: R` + `Preamp` + `Channel: all`）、`Filter N: ON PK Fc …`。
3. 备份当前 `peace.txt` 到 `%LOCALAPPDATA%\PeaceWpf\peace.txt.bak`（每次覆盖）。
4. 直接覆盖 `peace.txt`。EqualizerAPO 监视配置文件，写完就生效。
5. 更新本地已保存状态（两层、开关、平衡、preamp），脏标记清零。

启动时反过来：读 `peace.txt` 解析成主层；低音层、开关、平衡从 `ui-state.json` 恢复。文件里是合并结果，分不开两层，所以本地缓存优先。

### 一个环境坑

在这个 DSH 会话里，**从工作区 `D:\AHK\调音` 里启动的可执行文件**会被 DSH 的文件沙箱挡住对工作区外的写入：`File.WriteAllText` 抛 `UnauthorizedAccessException`，而同样内容用 PowerShell/Node 能写。把 exe 复制到工作区外再跑就正常，保存测试就是这么过的。开发时如果遇到“写不了 peace.txt”，先看是不是这个原因；正式安装（S10）不会在 DSH 里跑。

## 设计决定

- 点列表不可变，撤回栈存整份快照。
- 草稿与已保存两份状态；只有保存能改已保存。
- preamp 也进草稿，保存时才写文件（否则改 preamp 会触发 Peace 重写 `peace.txt`，把我们的内容冲掉）。
- 段数上限仍是 31，与 Peace 的槽位上限一致；写文件本身没有这个限制。
- 平衡用 `Channel` + `Preamp` 表达，居中时不写这两行。
- 备份放 `%LOCALAPPDATA%`：配置目录里建新文件可能没权限，已有文件可覆盖。

## 已知限制

1. `peace.txt` 里是合并结果，两层分不开；删掉 `ui-state.json` 就只剩主层。
2. Peace 自己切预设或改参数会重写 `peace.txt`，把前端的修改冲掉；下次保存会再写回去。S7 接管预设后再收口。
3. 点模型只认 PK；非 PK 段保存时会被写成 PK（进入左右模式会提示，面板底部常驻提醒）。
4. 点模型的频率上界是 20 kHz，原来的 22050 Hz 滤波器保存后会变成 20000 Hz。
5. 保存不触发 Peace 刷新，所以 Peace 隐藏界面的数据会和声音不一致；不要再从 Peace 那边调。
6. 开发环境的工作区沙箱问题见上。
