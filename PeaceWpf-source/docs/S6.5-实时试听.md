# S6.5 实时试听：改一下就出声

日期：2026-10-24

## 一句话结论

曲线、平衡、增益一改就写进 `peace.txt`，EqualizerAPO 读到就生效——不用先按保存。
按保存才把结果写回 `.peace` 预设；按取消把 `peace.txt` 还原，声音跟着退回去。

## 为什么只能这么接

EqualizerAPO 没有控制接口，它就是个读配置文件的引擎。要让它「现在」按新曲线跑，
唯一的路是把配置写进去、等它读。所以试听 = 提前写 `peace.txt`，没有别的通道。

## 怎么做的

| 环节 | 做法 |
|---|---|
| 触发 | 草稿一有变化（建点、拖动、改 Q、删点、撤回、重做）、平衡、增益、叠加开关，都调 `ScheduleSoundUpdate()` |
| 节流 | 距离上次写不足 150 ms 就排到点再写；内容与上次写的完全一样就跳过 |
| 写什么 | 两层按「叠加」开关合并，加上当前增益和平衡，生成整份 `peace.txt` |
| 第一次 | 写之前把原文读出来存着（`_previewOriginal`），顺带复制一份 `peace.txt.bak` |
| 取消 | 把存下的原文写回去；原文件本来不存在就删掉 |
| 保存 | 照旧写两份 `.peace` + `peace.txt`，然后清掉试听快照——保存后的状态就是新的原点 |
| 互斥 | 写入与还原共用一把信号量，避免「还原」被还在飞的试听写盖掉 |
| 写不进 | 状态栏直说「改动只在内存里，保存时会再试」，不假装修好了 |

## 一个顺带的调整

以前平衡和增益是「拖完就提交」，不进脏标记；现在编辑态下平衡也走试听，所以也算「还没保存」。
增益更进一步：任何状态下拖它都算「还没保存」，底部直接出现保存 / 取消——
否则会出现「声音变了、按钮却是灰的」这种鬼状态。非编辑态里平衡仍然拖完 450 ms 自动提交。

增益跟着「左右」预设走：每个预设各记一个 dB 值（存在 `ui-state.json` 的 `mainPreAmps` 里），
切预设推子跟着动；低音层没有增益，切它不会动。启动时以 `peace.txt` 里的 `Preamp` 为准。
曲线图把预增益加在每个采样点和手柄上，所以拖推子时整张图一起平移，形状不变。

## 验证

- 构建 0 警告，317 项自测全过（试听逻辑在 VM 里，靠实机验证）。
- 自测覆盖了预增益按预设分开记、大小写不敏感、随 `ui-state.json` 落盘读回、导入备份会带上。
- 临时 config 目录实机：增益从 `-0.3 dB` 拖到 `-6` →
  `peace.txt` 当场变成 `Preamp: -6.0 dB`（没有按保存）→ 点「取消」→ 回到 `-0.3 dB`。

## 代价与限制

1. 试听期间 `peace.txt` 里是「还没保存」的内容。程序崩溃会把它留在那儿（预设文件没写，重开还是原来的曲线）。
2. `peace.txt.bak` 只留最近一次；试听开始时会覆盖成「试听前的样子」，正好用来手动救。
3. 引擎重载有延迟（几十毫秒级），拖动很快时听起来是「跟手但略钝」；150 ms 的节流也是这个原因。
4. Peace 如果同时在跑，它改参数会重写 `peace.txt`，两边会打架——S7 的冲突检测要处理。
